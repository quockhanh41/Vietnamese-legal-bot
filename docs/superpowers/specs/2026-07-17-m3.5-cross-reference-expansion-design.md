# M3.5 — Cross-reference Graph Expansion into Chat (Design)

> **Date**: 2026-07-17 · **Milestone**: M3 item 3.5 · **Status**: approved design, pre-implementation
> **Plan**: [`docs/Plan_Giai_Doan_Cuoi_2026-07-10.md`](../../Plan_Giai_Doan_Cuoi_2026-07-10.md) row 3.5
> **Roadmap ref**: Gap #6 ("`_expand_context` chưa wire vào chat")

## 1. Problem

`EnhancedRetriever.retrieve(expand_context=True)` exists (`src/pipeline/retriever.py:180`)
but has two gaps that make it a no-op for chat:

1. **Not wired to chat.** `EnhancedRetriever` is used only by the `/search` REST
   endpoint (`src/api/main.py:458`). The chat orchestrator (`AdaptiveRAGPipeline`,
   `src/rag/orchestrator.py`) calls `vector_store.search_dense/search_hybrid`
   directly and never touches `EnhancedRetriever`.
2. **Fetches no text.** `EnhancedRetriever._expand_context` (`retriever.py:288`)
   only appends metadata stubs (`node_id`, `article`, `law_name`, `node_type`) to
   `expanded_chunks`. None of it reaches the LLM context, so even if wired it would
   add zero usable content.

Consequence: multi-hop questions where an article defers to another ("theo quy
định tại Điều Y") retrieve the referring article but not the referenced one, so the
answer is missing the operative rule. This is the last unwired piece of the Phase 2
knowledge graph.

## 2. Goal & non-goals

**Goal**: on the **complex route only**, after reranking, follow the knowledge-graph
edges from the top results, fetch the *text* of cross-referenced articles, and inject
them as additional numbered context blocks — so the LLM sees the referenced rule.

**Non-goals** (YAGNI / measure-first):
- No change to simple / medium / lookup routes, or to any non-complex behavior.
- No 2-hop expansion in v1 (1 hop only).
- No reranking of expanded blocks (they append after the reranked core).
- No new `/search`-side behavior; `EnhancedRetriever` is left as-is.

## 3. Feasibility (verified 2026-07-17 against the live `luat_law_ctx_v4` graph)

- Graph is populated: `data/metadata/graph.json` + SQLite `graph` table
  (`metadata_store.get_graph()`), 4970 nodes / 4943 edges.
- Edge mix: **3724 internal-target edges (75%)** point at `doc_…` nodes carrying
  `doc_id` + `article` (e.g. `{"id":"doc_215836_điều_100","doc_id":215836,
  "article":"Điều 100",...}`) — directly fetchable. **1219 external edges (25%)**
  point at `ext_…` nodes carrying `law_name` + `article` (e.g.
  `{"id":"ext_hàng_không...","law_name":"hàng không dân dụng Việt Nam",
  "article":"Điều 57"}`) — need name→doc resolution.
- Fetch mechanism exists server-side: `LegalVectorStore.scroll_article(doc_ids,
  article_number, cap)` (`src/db/qdrant_client.py:455`), already used by
  `CitationLookup.lookup`.
- Name resolution exists: `CitationLookup.resolve_doc(hint, year, doc_number)`
  (`src/rag/citation_lookup.py:372`), reachable via
  `self._get_citation_lookup()`.
- Node-ID convention is consistent: `f"doc_{doc_id}_{article.lower().replace(' ','_')}"`
  (`ArticleNode.make_id` == retriever `_expand_context`).

## 3bis. Graph prerequisite — article-level source nodes (discovered during execution, 2026-07-17)

**Blocker found after Tasks 1–2 landed:** the enriched graph (`data/metadata/graph.json`,
built against the live default collection `luat_law_ctx_v4_aiteamvn`) has **zero
article→article edges**. Every edge originates at a *document* node
(`document→article`: 3724, `document→external_ref`: 1219). The graph-based expansion
seeds from a retrieved *article* and follows its out-edges — of which there are none —
so expansion is a no-op in production.

**Root cause:** `src/pipeline/enricher.py:125` calls
`ref_extractor.extract(text=full_text, doc_id=doc_id, law_name=title)` over the whole
concatenated document, **without `current_article`**. The extractor already supports
`source_article=current_article` (`ref_extractor.py:39,152,177,…`); the caller just
never supplied it, so every `Reference.source_article` is `None` and
`LegalKnowledgeGraph.add_references` (`graph_builder.py:74-85`) falls back to a
document-level source node.

**Fix (decision: re-enrich, keep the graph-based design):** make the enricher extract
**per article**, passing the chunk's `article` payload value as `current_article`.

- **Node-id consistency (critical):** Task 1's expansion computes the seed node id as
  `f"doc_{seed.document_id}_{seed.article.lower().replace(' ','_')}"` from the *full*
  `article` payload string (e.g. `"Điều 43. Quản lý, khai thác quỹ đất ngắn hạn"`).
  The enricher MUST therefore pass that same full `article` string as `current_article`
  (NOT a shortened `"Điều 43"`), so the source node
  `make_id(doc_id, current_article)` equals the seed lookup id exactly. Target nodes
  keep the extractor's short `"Điều N"` form; Task 1's `_fetch_neighbor` recovers the
  number by regex, so short target ids fetch correctly.
- Re-running `scripts/run_enrichment.py --collection luat_law_ctx_v4_aiteamvn` rebuilds
  `store.db` + `data/metadata/*.json` and re-writes `is_in_effect` payloads on the live
  collection. This is idempotent w.r.t. M2's supersession state because the
  `VersionResolver` consolidation guard (commit `f55dc9e`) is in-code — but the M2 gates
  (is_in_effect counts, VBHN-supersession, hngd) must be validated post-run against a
  pre-run backup.

Tasks 1 and 2 are unchanged and correct once the graph carries article-source edges.
This prerequisite is implemented as Tasks 2A (enricher fix) and 2B (re-enrich +
validate), inserted before the measurement tasks.

## 4. Design

### 4.1 New method

```
AdaptiveRAGPipeline._expand_cross_references(
    results: List[SearchResult],
    is_comparison: bool = False,
) -> List[SearchResult]
```

Returns the extra blocks to append (never mutates `results`). Steps:

1. **Toggle / no-op guards.** If `self.cross_ref_expansion` is False → `[]`.
   Load graph; if it has no edges → `[]`.
2. **Adjacency + node map.** Build `{source_node_id: [target_node_id, ...]}` and
   `{node_id: node_dict}` from `graph["edges"]` / `graph["nodes"]`.
3. **Seeds.** Take the first `SEED_COUNT` (=3) results that have `doc_id` and
   `article`. For each, `node_id = f"doc_{doc_id}_{article.lower().replace(' ','_')}"`,
   then BFS **out-direction, `HOPS` (=1)** hop over adjacency → neighbor node IDs.
4. **Fetch text per neighbor** (in seed order, then neighbor order):
   - **Article node** (`node_type != "external_ref"`, has `doc_id`): extract the
     article number from `node["article"]` (regex `\d+[a-z]?`) →
     `scroll_article([doc_id], num, cap=1)`.
   - **External node** (`node_type == "external_ref"`): `resolve_doc(law_name)`;
     if it returns the *ambiguous all-docs fallback* (result set == every doc id)
     → **skip** (the referenced law isn't unambiguously in the corpus); else take
     the first resolved `doc_id` → `scroll_article([doc_id], num, cap=1)`.
5. **Dedup.** Skip any fetched chunk whose `(document_id, article)` already appears
   in `results` or in the already-collected expansion set.
6. **Temporal filter.** Annotate fetched chunks via `_annotate_phase2`; drop
   `is_in_effect is False` **unless** `is_comparison` (mirrors
   `_filter_in_effect(keep_superseded=is_comparison)`).
7. **Cap.** Stop once `MAX_EXPANDED` (=4) blocks are collected.
   > **Implementation note (M3.5):** the code applies the cap *during* collection
   > (steps 3–5) and runs the temporal filter (step 6) on the already-capped set,
   > i.e. the effective order is collect→cap→filter→cap rather than the
   > filter-then-cap reading of steps 6–7 above. This is an intentional efficiency
   > trade — `_annotate_phase2` is only ever called on the ≤4 capped blocks, never a
   > large neighbor set. It is always temporally correct (superseded blocks are never
   > shown unless `is_comparison`); the only cost is a marginal recall edge case
   > (if ≥`MAX_EXPANDED` superseded neighbors precede in-effect ones in edge order,
   > fewer than 4 blocks are returned). Accepted for v1.
8. **Safety.** The whole body runs under `try/except`; on any error, log and
   return `[]`. Expansion can only *add* context, never break the route.

### 4.2 Wiring (complex route only)

Both `_complex_pipeline` (non-stream) and the `else: # complex` branch of
`query_stream`, immediately **after** `results, rerank_scores = self._rerank_results(...)`
and **before** `results = self._expand_to_parent(results)`:

```python
expanded = self._expand_cross_references(results, is_comparison=is_comparison)
if expanded:
    results = results + expanded
```

Everything downstream is unchanged: `_expand_to_parent` (parent-Điều swap + dedup),
`_build_context` (numbers blocks `[n]`), `_build_citations` (block_index cards),
and — for the stream/non-stream complex path — `_compress_context`. Expanded blocks
therefore get `[n]` numbers and citation cards automatically, identical to any
retrieved block.

### 4.3 Constants

Defined at class or module level (tunable during eval):

```
SEED_COUNT   = 3   # top-N reranked results to expand from
HOPS         = 1   # graph BFS depth
MAX_EXPANDED = 4   # hard cap on appended blocks
SCROLL_CAP   = 1   # chunks fetched per referenced article
```

### 4.4 Measurement toggle

`self.cross_ref_expansion: bool = True` set in `__init__`. Eval instantiates the
pipeline (or flips the attribute) to run expansion OFF vs ON on the same questions.

## 5. Measurement — success criteria

Deterministic, LLM-generation-free, and immune to the ±0.1–0.2 run-to-run
confidence noise documented in M3.7.

### 5.1 New cohort
`data/eval/eval_set_multihop_v1.json`, ~10–12 questions. Each: the standard schema
(`id, question, type="multi-hop", difficulty, legal_sector, expected_behavior="answer",
ground_truth, expected_articles`), where **`expected_articles` lists BOTH the primary
article and the cross-referenced article**. Every label verified against the ingested
parquet (per the memory-noted "verify every label against parquet" rule; stale labels
have bitten this project twice).

### 5.2 Metric
New harness path runs the **real complex retrieval once per question** (rewrite →
multi-query → HyDE → hybrid → rerank), producing seed `results` and the `expanded`
set. For each question compute:
- `recall_before` = fraction of `expected_articles` present in `articles(results)`
- `recall_after`  = same over `articles(results + expanded)`

Because both are measured on the **same seed pass**, the delta is *purely*
expansion — no cross-run nondeterminism from rewrite/HyDE. Cost = 3 cheap LLM calls
(rewrite/multi-query/HyDE) per question, **no generation**.

**Positive gate**: `recall_after` > `recall_before` on the referenced-article
subset (i.e. expansion recovers cross-referenced articles that seed retrieval
missed), with no drop on primary-article recall.

### 5.3 B0 regression guard
The complex-route change is purely additive and never runs on refused/out-of-scope
queries (scope gate refuses pre-retrieval). Confirm the M3 anchor holds on the OOS
set: **refusal recall ≥ 0.7619, false_refusal ≤ 0.0972, no new OOS leak**. If the
positive gate fails, M3.5 is dropped-with-writeup per the plan's measure-or-drop rule.

## 6. Error handling & bounds

| Condition | Behavior |
|---|---|
| Expansion toggle off / no graph / no edges | return `[]` (route unchanged) |
| Seed missing `doc_id` or `article` | skip that seed |
| Neighbor node not in node map | skip |
| Article-number unparseable from node | skip |
| `scroll_article` returns nothing | skip |
| External `resolve_doc` → ambiguous all-docs | skip (law not unambiguously in corpus) |
| Duplicate `(doc_id, article)` | skip |
| `is_in_effect is False` and not comparison | drop |
| Any exception in the method | log, return `[]` |

Worst case: `SEED_COUNT` × (out-degree) `scroll_article` calls, hard-capped at
`MAX_EXPANDED` collected blocks. All fetches are server-side filtered Qdrant scrolls
(no embedding, no reranker) → cheap, no CPU-reranker latency exposure (the reason
expansion appends *after* rerank rather than entering the pool — see M2.6 bench:
rerank P95 @pool 50/100 = 2180/7582 ms).

## 7. Testing (TDD)

Unit (stub `metadata_store.get_graph()` + `vector_store.scroll_article`, no network):
- neighbor fetch appends referenced article text
- dedup: neighbor already in `results` is not re-added
- cap: never returns more than `MAX_EXPANDED`
- temporal: `is_in_effect=False` neighbor dropped when not comparison, kept when comparison
- external node resolves via `resolve_doc` → fetched; ambiguous-all → skipped
- no graph / no edges → `[]`; injected exception → `[]`
- non-complex routes and the returned-list ordering (seed blocks first, expanded last)

Then `make test` — the full suite (405 tests) stays green; no existing test changes
behavior because non-complex routes are byte-identical.
