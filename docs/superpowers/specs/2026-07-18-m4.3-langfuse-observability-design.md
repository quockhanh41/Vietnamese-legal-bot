# M4.3 — Langfuse Observability (Design)

> **Date**: 2026-07-18 · **Milestone**: M4 item 4.3 (first M4 sub-project) · **Status**: implemented 2026-07-18, live-verified
> **Plan**: [`docs/Plan_Giai_Doan_Cuoi_2026-07-10.md`](../../Plan_Giai_Doan_Cuoi_2026-07-10.md) row 4.3
> **Roadmap ref**: §3.9 ("Observability bằng Langfuse", Gap #3)

## 0. M4 decomposition (decided with user 2026-07-18)

M4 is three independent subsystems plus an eval; each gets its own spec → plan →
implementation cycle. Order chosen: **4.3 Langfuse (this spec) → 4.1+4.4
multi-turn memory + eval → 4.2 semantic cache**. Rationale: observability is the
roadmap's stated prerequisite for data-driven tuning, costs the least LLM budget
(Groq TPD exhausted 2026-07-18), and gives the memory/cache work tracing from day
one. Hard constraint recorded: 4.2 must follow 4.1 because the cache keys on the
*condensed* query embedding.

## 1. Problem

The pipeline has zero observability: no per-stage timing, no token/cost tracking,
no trace of the fallback chain. All runtime insight is 13 `print()` calls and the
final `latency_ms` figure. The M4 gate requires a Langfuse trace showing all
pipeline stages per query; roadmap §3.9 calls this the prerequisite for tuning the
refusal threshold with real data instead of belief. `LANGFUSE_*` keys exist
(user has a Langfuse Cloud Hobby account, free tier, 50K observations/month).

## 2. Goal & non-goals

**Goal**: one Langfuse trace per chat query with nested spans for route,
retrieval, rerank, cross-ref expansion, generation (with model/tokens/cost, and
failed fallback attempts), and verify — on both `/api/chat` and
`/api/chat/stream` — with tracing a strict no-op when keys are absent.

**Non-goals** (YAGNI / measure-first):
- No `session_id`/user tracking on traces (that lands with 4.1 memory).
- No tracing of `NaiveRAGPipeline` (not the production path).
- No Langfuse prompt management, evals, or scores API — tracing only.
- No global logging framework/config overhaul — only the 5 hot-path `print()`s.
- No self-hosted Langfuse (violates $0 constraint; Cloud Hobby is free).

## 3. Design

### 3.1. New module `src/observability.py` (the only new file)

Single responsibility: env-gated tracing setup, imported by orchestrator,
vector store, and gateway.

- Reads `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_HOST` at
  import. `TRACING_ENABLED = bool(public and secret) and
  os.getenv("LANGFUSE_TRACING_ENABLED", "true").lower() != "false"` — honors
  the SDK's official kill-switch so one env var silences both the decorators
  and the litellm callbacks without unsetting keys.
- **Enabled**: re-export `observe` from `langfuse`; register
  `litellm.callbacks += ["langfuse_otel"]` — the OTel-based integration the
  Langfuse docs recommend for SDK v3. Generations auto-nest under the active
  `@observe` span via the shared OpenTelemetry context (no metadata plumbing),
  and the callback covers failure events, making 429/fallback attempts
  visible — the highest-value diagnostic given recurring free-tier budget
  exhaustion. *(Amended 2026-07-18 during plan-writing: the originally
  specified classic `success_callback=["langfuse"]` + `existing_trace_id`
  metadata is the SDK-v2-era path and conflicts with the v3 `@observe` API;
  `langfuse_otel` removes the gateway change entirely.)*
- **Disabled** (missing keys, e.g. CI/tests/fresh clone): `observe` is an
  identity decorator that must support **both** `@observe` and
  `@observe(name=..., capture_output=False)` call forms; litellm callbacks are
  left untouched; `langfuse` is never imported.

### 3.2. Span map (one decorator line per point)

| Stage | Decorated point | Notes |
|---|---|---|
| trace root | `AdaptiveRAGPipeline.query` | non-stream root |
| trace root | `AdaptiveRAGPipeline.query_stream` | `@observe(capture_output=False)` — generator yields hundreds of tokens + `__STEP__`/`__CITATIONS__` markers; capturing them as output would bloat every trace. Answer text remains readable in the generation span. Span closes when the stream is exhausted = true end-to-end latency. |
| route | `_classify_and_scope` | |
| retrieval | `LegalVectorStore.search_hybrid` | covers simple/medium/complex routes at one point |
| lookup | `_lookup_pipeline` | citation-lookup route visibility |
| rerank | `_rerank_results` | |
| expand | `_expand_cross_references` | M3.5 feature traced from day one |
| generate | LiteLLM `langfuse_otel` callback (no decorator) | model, tokens, cost, latency per attempt, incl. failures; nests via shared OTel context |
| verify | `_post_process` | 6-signal confidence + verifier |

Input/output for decorated spans auto-captured from args/return (except
`query_stream` output, disabled above).

### 3.3. Gateway change (`src/llm/gateway.py`)

**None.** With `langfuse_otel`, LiteLLM generations inherit the active OTel
context automatically — `src/llm/gateway.py` is untouched (amended 2026-07-18,
see §3.1).

### 3.4. Structured logging (the "thay dần print()" slice)

Replace the hot-path prints — all 4 in `src/rag/orchestrator.py` — with
module-level `logging.getLogger(__name__)`. Levels assigned per message
(design review 2026-07-18):

| Site | Message | Level |
|---|---|---|
| `orchestrator.py:347` | reranker not available (skip) | `warning` |
| `orchestrator.py:739` | reranking failed (skip) | `warning` |
| `orchestrator.py:808` | cross-ref expansion failed (skip) | `warning` |
| `orchestrator.py:345` | reranker loaded (one-time lazy-load) | `info` |

*(Correction 2026-07-18 during plan-writing: `verifier.py:80` — counted as the
5th print — is a usage example inside a docstring, not runtime code. Left
untouched; 4 real prints, all in the orchestrator.)*

Rationale: with no global logging config (kept deliberately — uvicorn defaults),
Python shows WARNING+ via the lastResort handler, so the four degradation
messages stay visible in the terminal; the one-time load milestone moving to
`info` (invisible by default) is acceptable. Nothing qualifies for `debug`.
Enricher and scripts keep their prints (out of the hot path; surgical-change
principle).

### 3.5. Config surface

- `.env.example`: add `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`,
  `LANGFUSE_HOST=https://cloud.langfuse.com`.
- `requirements.txt`: add `langfuse`.
- Documented (no code): `LANGFUSE_TRACING_ENVIRONMENT` to segregate `dev` vs
  `eval` traces (tagging only — its official SDK semantics; never overloaded as
  a kill-switch); `LANGFUSE_TRACING_ENABLED=false` to silence tracing entirely
  for long eval runs. Eval tracing stays ON by default: eval runs are exactly
  the "real data" roadmap §3.9 wants for threshold tuning, and a full Tier-2
  run costs ~700 obs against the 50K/month quota.
- New `tests/conftest.py`: scrub `LANGFUSE_*` from the environment (or set
  `LANGFUSE_TRACING_ENABLED=false`) before src imports. Without it, any test
  importing `src.api.main` runs `load_dotenv()` (`main.py:13`) and leaks the
  developer's real keys into the test session — local `make test` would enable
  live tracing nondeterministically depending on import order.

## 4. Error handling

Principle: **tracing must never break or slow the pipeline.**

- Langfuse SDK batches and flushes on a background thread; network failures log
  a warning, never raise. No defensive try/except around decorators.
- Disabled mode is a pure identity decorator — zero overhead, zero network, no
  warnings in tests/CI.
- Short-lived scripts (eval.py): SDK's atexit hook flushes pending events — no
  eval.py changes needed.

## 5. Known risks & accepted noise

1. **SSE context propagation (verify early, not at the end).**
   `/api/chat/stream` iterates the generator via `iterate_in_threadpool`; each
   `next()` may run on a different worker thread with its own contextvars copy.
   Langfuse v3 (OTel-based) is designed to re-attach span context per iteration,
   but this is exactly where theory tends to break. A related check: the
   `@observe` spans (langfuse SDK tracer) and the `langfuse_otel` generation
   spans (litellm's tracer) must land in the **same trace** — they share trace
   IDs through the global OTel context, but export through separate pipelines.
   The implementation plan puts a live nesting check on `/api/chat/stream`
   immediately after wiring.
   **Fallback if nesting breaks**: `/api/chat` (sync, single thread) is
   guaranteed correct — the M4 gate demo runs on that path and the limitation is
   documented.
2. **Orphan traces from scripts.** `search_hybrid` calls with no active parent
   (eval Tier-1, enricher) each create a one-span trace; LLM calls from scripts
   likewise via the litellm callback. Accepted: 50K obs/month is ample;
   tag with `LANGFUSE_TRACING_ENVIRONMENT=eval` for UI filtering, or silence
   with `LANGFUSE_TRACING_ENABLED=false` when a run's traces aren't wanted.
3. **Cost figures are notional.** LiteLLM prices Groq/Gemini calls at list
   price; actual spend is $0 (free tier). Note this in the artefact doc.

## 6. Testing & verification

TDD order; all existing tests (421) must stay green; no network in CI.

1. **Unit — disabled mode**: without env keys, `observe` returns the original
   function unchanged (both call forms, `__name__` preserved), litellm
   callbacks untouched. Also with keys present but
   `LANGFUSE_TRACING_ENABLED=false` → same no-op behavior. The
   `tests/conftest.py` scrub (§3.5) makes this baseline deterministic
   regardless of the developer's `.env`.
2. **Unit — enabled mode** (monkeypatched dummy keys + module reload, no
   network): `"langfuse_otel"` registered in `litellm.callbacks`; `observe` is
   the real langfuse decorator.
3. **Unit — pipeline surface**: decorated methods keep their identity —
   `query_stream` is still a generator function, `__name__`s preserved.
4. **Live verify (gate evidence, needs LLM budget — may wait for TPD reset;
   1-2 queries suffice)**: run one real query through `/api/chat` and one
   through `/api/chat/stream` with real keys; confirm on the dashboard a single
   trace with route/retrieval/rerank/expand/generate/verify spans + token/cost
   on the generation; confirm a rate-limited fallback appears when it occurs.

**Gate (from M4)**: Langfuse trace shows the full stage set per query.
**Artefact**: `docs/notes/m4-observability.md` — dashboard screenshot + stage
map description (the plan's "bằng chứng production-grade trực quan nhất").

## 7. Design review outcome (2026-07-18)

Evaluated [`docs/notes/m4.3-langfuse-design-suggestions.md`](../../notes/m4.3-langfuse-design-suggestions.md):

- **Adopted (modified)**: explicit tracing kill-switch — but via the SDK's
  official `LANGFUSE_TRACING_ENABLED=false` (§3.1), not by overloading
  `LANGFUSE_TRACING_ENVIRONMENT` (that var tags traces; hijacking it would
  silently drop traces for anyone using it as documented). Deterministic test
  isolation via `tests/conftest.py` scrub (§3.5) — the real automation gap:
  `load_dotenv()` in `main.py:13` leaks developer keys into test sessions;
  nothing auto-sets the suggested `env=ci/test` values.
- **Adopted (corrected)**: deliberate log levels (§3.4) — but the actual
  prints are 3 degradation messages + 1 load milestone (the 5th "print" is a
  docstring example, see §3.4), so the mapping is `warning` ×3 / `info` ×1,
  not the suggested info/debug split (the prints the
  suggestion describes — route selection, latency, raw chunks — don't exist,
  and `info`-only would hide degradation under the default logging config).
- **Rejected**: auto-disabling tracing for `eval` — eval traces are the "real
  data" §3.9 exists for, and the quota concern is overstated ~70× (700 obs per
  full Tier-2 run vs 50K/month).
