# M3.6 — Verbatim-span Quotes (Design)

> **Date**: 2026-07-18 · **Milestone**: M3 item 3.6 · **Status**: approved design, pre-implementation
> **Plan**: [`docs/Plan_Giai_Doan_Cuoi_2026-07-10.md`](../../Plan_Giai_Doan_Cuoi_2026-07-10.md) row 3.6
> **Roadmap ref**: §3.2 follow-up ("verbatim-span quotes — verifier rẻ và chặt hơn NLI cho claim trích dẫn")

## 1. Problem

The answer format already hits most legal-RAG best practices — pinpoint citations
(`Điều`/`Khoản`), block-level source attribution (`[n]`), abstention gates, temporal
/ amendment awareness. The single largest remaining SOTA gap is **verbatim evidence**:
a `[n]` points at a whole retrieved block (a full `Điều`, up to 2000 chars), and each
"Chi tiết" bullet is a **paraphrase**. There is no thread tying a specific assertion to
the specific source words that back it.

Serious legal-AI tooling (and the academic attributed-QA / ALCE line) shows the reader
the **exact source text** for each claim, because it is verifiable down to the character.
That verifiability is also the point of M3.6 as a *verifier*: for a quotation-type claim,
a **string-match against the verbatim source is both cheaper and stricter than NLI**.
NLI (mDeBERTa, ~800MB, per-claim CPU inference) is fuzzy and lenient; an exact substring
match is free and exact. This is the strongest hallucination check available in the chain
— but only if the answer actually carries a verbatim span to match.

## 2. Goal & non-goals

**Goal**: each "Chi tiết" bullet carries **one verbatim span** quoted from the block it
cites. A new verifier stage **string-matches** each span against its cited block(s) and
records a new **observability-only** metric (`verbatim_match_ratio`) plus a warning when a
span does not match its source (hallucinated-quote evidence).

**Observability-first (non-negotiable):**
- Does **NOT** change `VerificationResult.passed` (still governed solely by
  `contradiction_ratio > 0.30`, per the calibrated pipeline's contract).
- Does **NOT** become a 7th confidence signal — the 6-signal `DEFAULT_WEIGHTS` and
  `REFUSAL_THRESHOLD = 0.700` are untouched in this milestone.
- Teeth (feeding confidence, or gating `passed`) are deferred to a later milestone,
  **after** the real-world match-rate distribution is measured (Phase 2).

**Non-goals** (YAGNI / surgical — user decision 2026-07-18):
- No change to the "Trả lời ngắn" or "Câu hỏi liên quan" sections.
- No change to citation cards / UI rendering, the API response model, or retrieval.
- No new confidence signal and no threshold recalibration in Phase 1.
- No multi-span-per-bullet support (one primary supporting quote per bullet).
- No wholesale format redesign (surface-confidence, effective-date prose, emoji removal
  were considered and explicitly deferred — see §7).

## 3. Answer-format change (one prompt edit)

`src/llm/prompts.py` `SYSTEM_PROMPT` gains one rule: under each "Chi tiết" bullet, on the
next line, emit a Markdown blockquote holding a **verbatim** span (copied character-for-
character, ≤ ~25 words) from one of the blocks the bullet cites.

```
### 📋 Chi tiết
- **Phạt tù** từ 1–5 năm (Điều 168 BLHS) [2]
  > "...bị phạt tù từ 01 năm đến 05 năm"
- Ý 2... [3]
  > "verbatim span from block 3"
```

**Anti-hallucination guardrail in the prompt**: if the bullet cannot be backed by a
verbatim span copied exactly from a cited block, the model must **omit the span** (never
invent or paraphrase-inside-quotes). A missing span is acceptable; a fabricated one is the
exact failure this milestone is built to catch.

## 4. Verifier: verbatim-span check (`src/rag/verifier.py`)

New Tier (call it **Tier 1.6**, sits after grounding, before NLI), observability-only.

### 4.1 Parse `(bullet → refs → span)` triples
Walk the "Chi tiết" section (reuse the existing section-boundary logic from
`_groundable_claims`). For each bullet, look at the **immediately following** blockquote
line(s) (`>` prefix) as that bullet's span; **consecutive `>` lines are joined** (with a
single space) into one span. A bullet with no following blockquote has `span = None`.

### 4.2 Normalize before matching
Applied to **both** the span and the candidate block text:
- casefold (lowercase)
- collapse all whitespace runs → single space
- normalize quote chars (`" " „ « » ' '` → straight `"`/`'`) and strip the outer quote
  characters wrapping the span
- normalize dash variants (`– —` → `-`)
- **keep Vietnamese diacritics** (semantically load-bearing — do not strip)

### 4.3 Match rule
A span matches iff `normalized_span` is a **substring** of `normalized_block[n]` for **any**
`[n]` the bullet cites. Guard: a normalized span shorter than **10 characters** is treated
as invalid (does not count as a match — prevents trivially-matching fragments from
inflating the ratio).

### 4.4 New `VerificationResult` fields (all default-empty)
- `verbatim_spans: List[str]` — the spans extracted, in bullet order
- `verbatim_match_flags: List[bool]` — per-span match result
- `verbatim_match_ratio: float` — `matched / spans_present` (0.0 when no spans)
- `unverbatim_spans: List[str]` — spans that failed the match (**the hallucination
  evidence** — the highest-value artefact of this milestone)
- `bullets_missing_span: int` — count of "Chi tiết" bullets with no span (prompt-
  compliance observability; not a failure)

### 4.5 Warning (observability only)
When `unverbatim_spans` is non-empty, append
`⚠️ N trích dẫn nguyên văn không khớp nguồn.` to `result.warnings`. This must **not** touch
`result.passed`, `has_contradiction`, or any confidence signal.

## 5. Calibration protection (the load-bearing invariant)

The blockquote spans are verbatim source text. If they leak into the inputs of the three
answer-derived calibrated signals, they perturb a pipeline whose threshold is calibrated:
- `_context_overlap(answer, context)` (`confidence.py:414`) extracts keywords from the
  **whole answer** → verbatim source text would inflate overlap.
- `_split_claims` (NLI premise/claims) and `_groundable_claims` (grounding) walk answer
  lines; a `>` line matches neither the bullet nor the numbered pattern, so today it would
  fall through and be counted as a spurious claim.

**Invariant**: strip every blockquote (`>`) line from the answer text **before** it feeds
`_context_overlap`, `_split_claims`, and `_groundable_claims`. After stripping, those three
signals see byte-for-byte the same claim text they saw before M3.6, so the calibrated gate
is not perturbed by the span-carrying format. A shared helper (e.g.
`context_blocks.strip_blockquotes(text) -> str`) is the single point that does this, reused
by both the verifier and the confidence scorer.

> This invariant is what makes "observability-only" honest. It is verified directly by a
> regression test (§6, last case), not merely asserted.

## 6. Testing (Phase 1 — deterministic, no LLM budget)

TDD. Synthetic answer fixtures + synthetic numbered context; no model calls. Cases:
1. **Exact match** — span copied verbatim from the cited block → `match_flag True`,
   `verbatim_match_ratio == 1.0`.
2. **Whitespace/case/quote-style differ** — span differs only in normalized-away ways →
   still matches.
3. **Fabricated span** — span not present in any cited block → `unverbatim_spans` non-empty,
   warning appended, **`passed` unchanged**.
4. **Missing span** — bullet with no blockquote → `bullets_missing_span` increments, not
   counted against the ratio.
5. **Multi-block cite** — bullet cites `[2][3]`, span lives in block 3 → matches.
6. **Too-short span guard** — normalized span < 10 chars → not a match.
7. **Calibration-protection regression** — for the same logical answer with vs. without
   blockquote lines, `_split_claims`, `_groundable_claims`, and `_context_overlap` produce
   **identical** output. This pins the §5 invariant.

## 7. Measurement & definition of done (budget-aware)

- **Phase 1 (now, 0 LLM budget)**: prompt edit + Tier-1.6 span checker + strip-blockquotes
  invariant + full unit-test suite green. This ships a correct, fully-tested checker.
- **Phase 2 (when Groq budget resets — batched with the already-pending 3.4 Task 5 + 3.5
  B0 guard)**: run the eval cohort to (a) measure the **`verbatim_match_ratio`
  distribution** [new portfolio artefact — "how often the model quotes faithfully"], and
  (b) run the **B0 regression guard** (the prompt changed, so answer text shifts): target
  `refusal_recall ≥ 0.7619`, `false_refusal ≤ 0.0972`, **no new OOS leak**. If the format
  change moves B0 outside the gate, adjust or roll back the prompt before declaring done.

**Done = Phase 1 merged (code + green tests) + Phase 2 gate passed.** Phase 1 alone is a
mergeable, self-contained increment; it does not claim the milestone complete until Phase 2
confirms no calibration regression.

## 9. Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| LLM paraphrases inside quotes → low match rate | Medium | Observability-first: Phase 1 just measures. Prompt says omit-if-not-verbatim. Match-rate distribution is itself the artefact. |
| Prompt change shifts B0 (answer text feeds calibrated signals) | Low–Med | §5 strip invariant keeps calibrated inputs unchanged; Phase 2 B0 guard confirms empirically before "done". |
| Blockquote parsing misattributes a span to the wrong bullet | Low | Span = blockquote line(s) *immediately following* a bullet; covered by unit tests (cases 4, 5). |
| Confounding with pending 3.4/3.5 measurement in the same batch | Low | `verbatim_match_ratio` is a new independent metric; B0 guard is per-change — run M3.6's answers as their own eval pass. |
